# Grok bot 风格图标生成

一条参考图 → 一张成图约 1 分钟。**规范优先于还原度**：这是本技能唯一的主线，也是第一次尝试翻车的原因（见 `references/case-2026-09-25.md`）。

## 本机环境事实

| 项 | 事实 |
|---|---|
| 规范正本 | 仓库根 `grok-bot-prompt.txt`（头像版）。全身版的差异见第 1 节，**不要改正本** |
| Token | `MODELSCOPE_API_TOKEN` 在 <toolchain-mgr> 的 `[env]` 段，**普通 Git Bash 取不到**（`env \| grep` 是空的） |
| 调用方式 | 一律 `<toolchain-mgr> exec -- node <script>`，不要把 token 导出到别处或写进文件 |
| 端点 | `https://api-inference.modelscope.cn/`，异步任务制，不是 OpenAI images 契约 |
| 模型 | `Qwen/Qwen-Image-2.1`（支持 `image_url` 图生图）。模型 ID 会随上下架变，报错先查模型页范例 |
| 账号门槛 | 需 `ms-` Access Token + 绑定阿里云账号 + 实名认证；额度按魔粒扣减（轻量 0.5 / 主流 1 / 旗舰 2 每次） |

## 0. 开工前必须确认的三件事

**用 AskUserQuestion 一次问齐，不要逐条来回问。** 缺就问，不要猜：

1. **参考图路径**（本地 PNG 直接传，会转 base64，不需要托管 URL）。
2. **头像版还是全身版**。头像是原规范（超近景、15～20° 歪头、不画身体）；全身版是 Q 版立绘（2.5～3 头身、完整入画、不歪头那么多）。
3. **签名元素与规范冲突时听谁的**。例：角色有一只眼被蝴蝶/刘海/眼罩遮住——规范优先级第一条要求"双眼完整可见的黑色胶囊眼"，默认按规范走（把遮挡物移到不遮眼的位置）；但那是角色的招牌，用户可能反过来要它。**先问一次，记下结论再跑**。

## 工作流（复制这张表逐项推进）

```
- [ ] 1 看图：确认三项核心识别特征 + 真实存在的待排除元素清单
- [ ] 2 抄第 1 节的硬指标表，逐条填值（头像版/全身版选一列）
- [ ] 3 用 assets/prompt-template.txt 填空 → 正向提示词文件
- [ ] 4 用 assets/negative-template.txt 填空 → 负面提示词文件（排除项只放这里，不放正向）
- [ ] 5 跑 scripts/ms_gen.mjs（带 --image 走图生图）
- [ ] 6 按第 4 节逐条核验，输出 ✓/△/✗ + 归因
- [ ] 7 未达标 → 只改一个变量，回到第 5 步
```

第 3、4 步的产物写成 `.txt` 文件传给脚本，**不要把中文提示词内联进命令行**（zh-CN 在 Git Bash / PowerShell 里有编码陷阱）。

## 1. 硬指标清单（逐条落地，漏一条就算没做对）

写提示词前先把这张表抄进草稿，一条一条填，**不要凭印象写"极简 2D 风格"这种弱词**：

| 硬指标 | 头像版 | 全身版 |
|---|---|---|
| 画布 | 1:1 | 1:1 |
| 景别 | 超近景，头部占大部分，边缘自然裁切 | 头顶到脚底完整入画，不裁切 |
| 身体 | **不画身体和手** | 2.5～3 头身 Q 版，头大圆、身短小 |
| 倾斜 | 顺时针 15～20°，双眼随头部一起倾 | 顺时针 5～10°（很轻微，几乎正） |
| 眼睛 | 纯黑胶囊，高:宽 = 2.5～3，等大平行，长轴⊥两眼中心连线，内部无任何细节 | 同 |
| 嘴鼻 | 一律不画 | 一律不画 |
| 腮红 | 低饱和小椭圆，无描边无闪光 | 同 |
| 肤色/发色 | **取自原图**，不许统一成固定色 | 同 |
| 识别特征数量 | **最多约三项**，宁少勿多 | 同 |
| 上色 | 几乎无描边、色块为主、基础色最多加一档轻阴影 | 同 |
| 背景 | 铺满画布的近纯白，无物体 | 同 |
| 排除 | 文字/数字/Logo/水印/边框/徽章/闪粉/粒子/光晕/镜头光斑 | 同 |

**冲突优先级**（原规范给定，顺序不可调）：黑色胶囊眼 → 无嘴无鼻的圆润机器人脸 → 双眼完整可见的构图 → 原图基础色与核心识别特征 → 其他细节。

## 2. 组装提示词

用 `assets/prompt-template.txt` 与 `assets/negative-template.txt` 填空，结构固定为七段：

1. **目标句**：一句话说明"把参考图中的 X 转换为 Grok bot icon 风格的极简 2D 全身站立机器人图标"。
2. **从原图只提取三项核心识别特征**：写成编号列表，每项是"大轮廓 + 颜色"，不要罗列细节。
3. **其他全部省略**：把原图里**真实存在**但规范要丢的东西点名（写实手指、密集刺绣、卡牌边框、SSR 字样、暗色渐变背景……）。这一项是排除清单，不是套话——写不出具体项说明你还没看图。
4. **构图 / 脸部 / 眼睛 / 头发与头饰 / 服装与身体 / 上色 / 背景**：按第 1 节的表逐条落文字。

要点：

- **`image_url` 是图生图，必用**。纯文生图（不传参考图）会把服装层级信息丢掉——露肩、多层薄纱、大面积金饰这类纯视觉信息文字承载不动。
- **"不要 X" 不要留在正向里**。Qwen-Image 对正向文本的否定跟随很弱，排除项一律进 `negative_prompt` 字段（上限 4000 字符，正向 prompt 上限 2000）。
- 中文提示词直接可用，不必翻英文（Qwen-Image 原生中文）。

## 3. 调用

```bash
cd <repo-root>
<toolchain-mgr> exec -- node .agents/skills/grok-bot-icon/scripts/ms_gen.mjs \
  --image "<参考图.png>" \
  --prompt <正向提示词.txt> --negative <负面提示词.txt> \
  --size 1328x1328 --steps 40 \
  --out <输出.png> --verbose
```

参数事实（都实测过，别再试错）：

- **没有 `sampler`/`scheduler` 字段**。服务端默认调度器是 FlowMatchEuler，等价 ComfyUI 的 `euler`，所以"用 euler"这条不用传也满足。
- **`seed` 取值域 `[0, 2^31-1]`，不能传 `-1`**。要随机就**省略 `--seed`**；要复现就传一个具体整数。
- `steps` 取值域 `[1,100]`；`size` 对 Qwen-Image 上限 1664×1664，`1328x1328`（官方 1:1 预设）可用，输出尺寸听请求的，不会被参考图比例拉回。
- `image_url` 要**数组包 data URL**：`["data:image/png;base64,…"]`。2.5 MB PNG（base64 约 3.4 MB）能过，没有撞到体积限制。
- POST 响应里的 `task_status: SUCCEED` 只代表**任务受理**，图好了要看 `GET /v1/tasks/{task_id}`。脚本已处理，人工 curl 时别被骗。
- 耗时基线（**条件不同不可互比**）：1024² 默认步数纯文生图 ≈ 28 s；1328² + 40 步纯文生图 ≈ 52 s；同配置带参考图 ≈ 66 s。

## 4. 结果核验（必做，别只说"好不好看"）

拿到图后按第 1 节的表**逐条**给结论，格式：

```
✓ 落地项 …
△ 轻微偏差：具体是哪条、偏了多少（数值，如"头身比约 2.8""珠串画了 8 颗，规范要 3~5 颗"）
✗ 未达标项 + 归因（提示词没写 / 写了但模型没跟 / 规范冲突我替你定了）
```

一次只改**一个变量**再重跑，否则无法归因。改措辞无效两次以上就换路线（调 `steps`、换 `size`、或回到本地 ComfyUI 用 ControlNet 锁姿态）。

## 常见坑

- **把"还原角色"放在"守规范"之上**——最容易犯的错，结果会画成立绘而不是图标：丢了 Q 版头身比、保留了规范明令禁止的托下巴写实手势、平涂强度不足。详见 `references/case-2026-09-25.md`。
- **规范里的数量上限是真的**："核心识别特征最多约三项"就只留三项，列到七八项等于抵消了"省略细节"这条要求。
- **遮挡物要移位而不是删掉**：蝴蝶/刘海/眼罩遮眼时，按优先级把遮挡物移到额侧或发间，保住双眼完整可见——删掉它反而丢了识别特征。
- **别用第三方模型转写的提示词直接跑**：它可能看着**另一张图**写排除清单（本项目案例里出现了参考图根本不存在的 SSR/卡牌边框/月亮）。拿到先和参考图对一遍。
- **赤足 vs 鞋块**这类与原图冲突的规范条目，是风格覆盖，不是 bug，但要先确认。
- 生成图落在哪里由 `--out` 决定；技能目录不放产物。
