一次把"能不能调 API"和"怎么把 grok-bot 规范写对"两件事一起趟平的过程。四次调用，两次翻车，最终通过件在 `assets/case-grok-male-01.png`。

## 翻车归因（这是本技能存在的原因）

**#2 的根本错误：把"还原参考图的角色信息"放在了"守风格规范"之上。** 我当时写出的提示词是一段角色立绘描述，丢了四条硬指标：

- **2.5～3 头身 Q 版比例**——完全没写，直接按正常人体走。
- **"不要托下巴"**——我反而主动把它当"原图招牌姿势"保留了，正好撞上规范明令排除的"写实手部托下巴姿势"。
- **平涂强度**——只写了"极简 2D"这种弱词，没有量化到"色块为主、最多加一档阴影"。
- **排除清单**——只写了泛化的"文字水印粒子"，没针对源图点名。

还有一条：规范说"核心识别特征控制在最多约三项"，我列了七八项，等于把"省略细节"这条要求自己抵消掉了。

**#3 的收获与代价**：图生图确实救回了纯文字搬不动的信息（露肩、多层半透明垂袖、金色胸甲面积、多条青绿流苏），但风格执行度下降——成品仍有明显柔和渐变，接近厚涂。同时暴露 #2/#3 两次**同时改了两个变量**（提示词框架 + 是否传图），所以那次对比不能归因给"图生图"单项。这条纪律写进了 SKILL.md 第 4 节。

**#4 才对了**：用户直接给出按规范重写的版本作为模板，我只替换"从原图提取"那一段。

## #4 的三项识别特征（对照 `assets/prompt-template.txt`）

1. 银白偏冷长发，头顶蓬松卷曲，一侧编入垂至腰下的长辫，辫中夹紫色发丝。
2. 半透明蓝白蝴蝶——**移位**到额头侧边与发际之间。
3. 紫黑交领长袍 + 白色毛皮披肩 + 金色兽形胸扣 + 黑色圆珠项链。

**冲突决定**：原图招牌是蝴蝶遮右眼，但规范优先级第一条是"两只无装饰的黑色胶囊眼"、第三条是"双眼完整可见"，所以蝴蝶移位而不是保留遮眼，同时在 `negative_prompt` 里加 `蝴蝶遮住眼睛`、`眼罩`。**这个决定应当先问用户**——签名元素被移走可能是用户不能接受的。

## #4 核验结果

✓ 头身比约 2.8（规范 2.5～3）· 胶囊眼高宽比约 2.6 且等大平行纯黑 · 无嘴无鼻 · 浅粉紫椭圆腮红 · 苍白冷白圆脸 · 手部圆润无写实手指 · 脚部圆角深色块 · 几乎无描边色块为主 · 近纯白背景无物体 · 头顶脚底完整入画 · 双臂自然下垂 · 1:1 1328²

△ 头部 5～10° 顺时针倾斜几乎看不出，接近正 · 金色兽扣变成飞鸟剪影（规范只要求"最简轮廓"，擦边通过）· 黑色珠串约 8 颗，规范要求三五颗

## 一条外部输入要警惕

当时对照用的第三方（DeepSeek）转写版本，排除清单里写着"SSR 文字、卡牌边框、名字文字、紫色背景、月亮圆环、山川"——**这些在参考图里根本不存在**（参考图是纯白背景无文字）。说明它当时看的是另一张图，或者是编的。拿到任何第三方转写的提示词，先和参考图逐条对一遍再用。

## 可复现命令

```bash
cd <仓库根>
node .agents/skills/grok-bot-icon/scripts/ms_gen.mjs \
  --image "<参考图.png>" \
  --prompt <填好的正向模板> --negative <填好的负面模板> \
  --size 1328x1328 --steps 40 --out out.png --verbose
```

不传 `--seed` = 随机（等价 ComfyUI 的 `-1`，但 API 不接受 `-1`）。要复现同一张图就传固定整数。
